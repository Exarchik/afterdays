# Перехід на Arcade: GPU-рендеринг мапи й арени

Перший етап: мапа, арена, істоти, позначки та ефекти малюються Arcade 3.3.3
у справжньому OpenGL-вікні, вбудованому в ігрове вікно Windows.
Кадр не перетворюється на картинку Tkinter і не копіюється з GPU на CPU.

Це **ще не повний перенос ігрового інтерфейсу**: рамка вікна, кнопки,
інвентар, торгівля, діалоги й допоміжні вікна залишаються Tkinter.
Редактор залишається Tkinter; його запуск і залежності не змінені.

## Запуск

1. Python 3.10+ (64-bit), Windows, драйвер із підтримкою OpenGL 3.3+.
2. Один раз запустити `INSTALL_GAME.bat` (або `python -m pip install -r requirements-game.txt`).
3. `START_WINDOWS.bat` запускає GPU-рендерер.
4. Для порівняння або відновлення старого рендерера: `START_WINDOWS.bat --renderer=tk`.
   Також підтримується `AFTERDAYS_RENDERER=tk`.

Для обох режимів збереження й ігрові правила однакові. Автоматичного прихованого
перемикання на Tk немає: відсутність Arcade або помилка OpenGL має бути видима.
Вбудовування використовує Windows HWND та внутрішні поля pyglet; версія Arcade
зафіксована, а оновлення pyglet потребує повторного GUI-тестування.

## Побудова рендерера

- `arcade_scene.py`: незалежна від GUI сцена, теги, переміщення та трикутники.
- `arcade_canvas.py`: адаптер команд, GPU-текстури, SpriteList і буфери геометрії.
- PNG-атласи читаються напряму. Масштабування тайлів виконує GPU; нових PNG немає.
- Сусідні тайли групуються в SpriteList; однакові групи команд повторно використовують
  GPU-буфери. Текст та групи буферів мають обмежені кеші.
- Незмінна сцена не перемальовується щотакту. Старі ігрові таймери збережені.
- Штриховані області представлені прозорістю; геометрія ліній і текстовий растеризатор
  відрізняються від Tk, тому можливі незначні візуальні відмінності.
- `app.canvas.metrics` містить GPU, час останнього рендеру, кількість груп і текстур.
  Це час рендерера, а не всього ігрового ходу.

## Перевірка

`python -m unittest test_arcade_scene`

`python tools/check_arcade_ui.py` відкриває тестове вікно, перевіряє світ, арену,
зміну розміру та очищення ресурсів; використовує окрему тестову гру.
Не перезаписує збереження гравця.

Перевірено на Intel UHD Graphics 770: світ, арена, пересилання миші й клавіатури,
зміна розміру, Tk-накладка поверх OpenGL та закриття вікна. На тестовому відкритому
фрагменті середини мапи після прогріву: приблизно 11 мс на підготовку та малювання
кадру. Початкове завантаження текстур і компіляція буферів дорожчі. Це не вимірювання
повного ігрового ходу й не доказ усунення лагів у конкретному збереженні.

51 тест (сцена, фракції, відновлення після смерті, діалоговий текст, атласи) проходить.
Окремо `test_event_notices.test_world_notices_are_serial_across_batches_and_pause`
виявляє стару невідповідність: очікує мінімум 2 секунди повідомлення, тоді як
`adventure_ui.py` у HEAD вже використовує мінімум 1 секунду. Цю логіку міграція не змінює.
Також перевірено запуск редактора й резервного Tk-рендерера без Arcade.

Наступний етап: перенесення ігрових панелей і модальних інтерфейсів на Arcade UI
та відокремлення контролера гри від Tk. Після цього можна прибрати Tk із запуску
самої гри, зберігши його тільки для редактора. Перед цим потрібне порівняння
продуктивності на збереженні, де спостерігається уповільнення.
